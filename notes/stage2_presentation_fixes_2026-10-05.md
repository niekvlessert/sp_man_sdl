# Stage 2 object placement, red tubes and launcher wrecks

## Findings and fixes

The Stage-2 native scenery path did not compensate the one-column origin of
its D988/R18 presentation. At world X=$04DA (1242 pixels), the canonical name
row exactly equals original OpenMSX VRAM $C000, while native R18 contributes
an extra eight-pixel display displacement. Apply the same native origin
compensation already used by Stage 1, including the current camera step.
This keeps native continuous movement aligned with object coordinates during
horizontal, diagonal and vertical sections.

Type $29 cannons, $2B launchers, $2E tube installations and $6B wrecks were
also going through the coarse overlay and world-comparison passes. These
passes applied camera interpolation twice or classified changing artwork as
scenery. Give each complete assembly one native rendering owner; include the
wreck in that ownership so destruction cannot leave an old launcher fragment.
The original persistent wreck itself remains: $7CC3 retains +3E=$04 for $2B,
and $9B38 eventually selects $6B tile frame 4.

The green/red moving heads are type $31. Native implemented their movement
but omitted fixed $5CF6-$5D3A entirely. This routine stamps tile pair CC/CD:
variant zero runs down from head Y+2; nonzero runs up from head Y. It stops
when the original terrain property is exactly 3. Native now builds both
original tube directions, and terrain probes exclude their previous stamp
so they cannot collide with their own tube. SDL renders the head and tube
on the same camera clock.

## Validation

Build succeeds. `space-manbow-stage2-presentation-test space_manbow.rom`
checks six original tube scripts, both moving-head tube directions and solid
terrain stops, all four native camera phases against original scenery, and
that a destroyed launcher changes only pixels inside its original wreck.

Existing Stage 2, Stage 3/4, Stage 5–9, late enemies, boss visuals, boss
regressions, combat, timeline, continuous scroll, scroll feedback and Stage
8/9 presentation checks pass (12 targeted executables including the new one).

This is a focused correction of the reported visual faults, not an exhaustive
claim of Stage-2 gameplay parity. The broader gaps remain documented in
stage2_fidelity_report_2026-10-04.md.

## Follow-up 2026-10-07 — descending $2A machines

The large teal double-cylinder in the screenshot is type $2A, generated by
$53, rather than a tile obstacle. Its native sprite now uses the shaft origin
without the SAT +7 border offset. The original entity position and $8338/$6C3A
movement remain unchanged. Presentation interpolates only horizontal camera
compensation, because this family deliberately ignores vertical camera motion.
$2A and the similarly aligned $2C tube modules are excluded from the coarse
sprite classification passes so their old +7px copies cannot leave fragments.
The presentation regression checks the complete 48px assembly at all four
camera phases, including the absence of pixels outside its correct bounds.

## ROM follow-up — $53 controller placement

Bank05 $9984 contains `3A 18 CA 3D C8 DD 34 20 DD 35 0A C9`:
while CA18 is 1 it returns; otherwise it sets the +20 latch and decrements
the controller's coarse X once (eight pixels). Bank09 $7BA2 copies C0D5
into CA18 during scrolling; $7BE9 clears it when gated. The native X<=13
heuristic omitted the actual displacement and used the wrong trigger.
The handler now consumes the real camera direction and follows that ROM
branch. Existing children retain their coordinates; later children inherit
the shifted coarse X through $6926, which copies +0A without its fraction.

Original OpenMSX audit captures 097..100 show direction 1 and latch 0;
101..134 show direction 3, latch 1, controller X=$0D00 and subsequent
$2A children at X=$0D00. A native session now reaches the same $0D00
position at the transition. Regression checks cover the direction trigger,
one-time displacement, unchanged existing children, fractional spawn
quantization, and the natural session position.

## Boss palette inheritance

Stage-2 boss asset root bank10 $8709 has an empty palette preamble (`FF`).
It retains the live stream's bank27 $A95D green palette, including its black
backdrop. `decode_stage_boss_palette` previously started from the initial
blue/brown stage palette, overwriting the correct arrival colours when the
boss scene became active. It now inherits the final-sector palette for Stage
2, so both scene activation and restoration after hit flashes stay green.
The boss palette regression compares all 16 registers with original OpenMSX
capture 170 and checks green/black pixels in both render paths before damage.
Stage 2, Stage-2 presentation, boss visuals and boss palette tests pass.
